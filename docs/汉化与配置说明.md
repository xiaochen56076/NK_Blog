## 1. 常用命令

| 命令 | 作用 |
|---|---|
| `pnpm install` | 安装依赖（必须用 pnpm，`package.json` 里有 `only-allow pnpm` 限制） |
| `pnpm dev` | 本地开发服务器，默认 <http://localhost:4321> |
| `pnpm build` | 生产构建：`astro build` 生成 `dist/`，再跑 `pagefind --site dist` 生成搜索索引 |
| `pnpm preview` | 预览构建产物（**只有在这里搜索功能才可用**） |
| `pnpm new-post` | 新建文章（`scripts/new-post.js`） |
| `pnpm sync-avatar` | 从 GitHub 重新同步头像到本地（见第 9 节） |
| `pnpm check` | Astro 类型检查 |
| `pnpm lint` / `pnpm format` | Biome 检查并修复 / 格式化 `src` |

## 4. 站点总配置 `src/config.ts`

### siteConfig

| 字段 | 作用 | 说明 |
|---|---|---|
| `title` | 站名，显示在导航栏左侧、浏览器标题、OG 卡片 | 当前 `Nskdfh 的博客` |
| `subtitle` | 副标题，仅用于首页标题 `站名 - 副标题` | 当前 `个人博客` |
| `lang` | 界面语言，决定读哪个 i18n 文件 | 可选 `en` `zh_CN` `zh_TW` `ja` `ko` `es` `th` `vi` `tr` `id` |
| `themeColor.hue` | 主题色相 0–360（红 0 / 青 200 / 粉 345） | 当前 250 |
| `themeColor.fixed` | `true` 则对访客隐藏调色板按钮 | 当前 `false` |
| `banner.enable` | 是否显示顶部大图 | 当前 `false`（图已配好，改 `true` 即启用） |
| `banner.src` | 大图路径/URL | 以 `/` 开头 = `public/` 目录；`http(s)://` = 原样引用；否则相对 `src/` |
| `banner.position` | 大图裁切位置 | `top` / `center` / `bottom` |
| `banner.credit` | 图片署名按钮 | `enable`、`text`、`url` |
| `toc.enable` / `toc.depth` | 右侧文章目录开关 / 最大层级 | depth 只能 1–3 |
| `favicon[]` | 自定义站点图标 | 留空则用 `src/constants/icon.ts` 的默认值；文件放 `public/favicon/` |

### navBarConfig

`links` 数组，元素可以是预设或自定义项：

- 预设：`LinkPreset.Home`、`LinkPreset.Archive`、`LinkPreset.About`（文案自动取 i18n 的 主页/归档/关于）
- 自定义：`{ name: "GitHub", url: "https://github.com/xiaochen56076", external: true }`
  - `external: true` 会显示外链图标、在新标签页打开
  - 站内链接**不要**带 base 路径（会自动添加）

### profileConfig（侧栏个人资料卡）

| 字段 | 说明 |
|---|---|
| `avatar` | 头像。以 `/` 开头 = `public/`；`http(s)://` = 原样引用；否则相对 `src/` 并经 Astro 优化 |
| `name` | 昵称（也用于页脚版权行、RSS 标题、`<meta name="author">`、文章的 JSON-LD） |
| `bio` | 简介 |
| `links[]` | 社交图标按钮，`{ name, url, icon }`；`icon` 取 [icones.js.org](https://icones.js.org/) 的图标码，需要对应图标集已安装（已装 `fa6-brands`、`fa6-regular`、`fa6-solid`、`material-symbols`） |

### 其它

- `licenseConfig`：`enable` / `name` / `url`，控制文章底部许可协议块
- `expressiveCodeConfig.theme`：代码块配色主题（本主题只支持暗色底，建议选暗色系）
- `musicConfig`：侧栏音乐播放器（开关、曲目列表、`playlistUrl` 接口地址）—— 详见 **`docs/音乐播放器说明.md`**

## 7. 界面文案与国际化

**机制**：组件调用 `i18n(I18nKey.xxx)`，键定义在 `src/i18n/i18nKey.ts`，各语言文案在 `src/i18n/languages/<语言>.ts`，由 `siteConfig.lang` 决定读哪个文件（`translation.ts` 做映射，`zh_CN` → `zh_cn` 键）。

**要改界面用词，只改 `src/i18n/languages/zh_CN.ts` 一处**，例如把「主页」改成「首页」、把字数单位「字」改成别的。

| 文案键 | 出现在界面 |
|---|---|
| `home` / `archive` / `about` | 导航栏；`about` 同时作为关于页标题 |
| `search` | 搜索框 |
| `categories` / `tags` | 侧栏分类卡、标签卡标题 |
| `wordCount` / `wordsCount` | 首页卡片、文章页的字数 |
| `minuteCount` / `minutesCount` | 首页卡片、文章页的阅读时长 |
| `uncategorized` / `noTags` | 文章元信息里的「未分类」「无标签」 |
| `postCount` / `postsCount` | 归档页篇数统计 |
| `themeColor` / `lightMode` / `darkMode` / `systemMode` | 显示设置面板、亮暗切换 |
| `author` / `publishedAt` / `license` | 文章底部许可协议块 |
| `more` | 各侧栏小卡的「更多」 |

## 8. 写文章

### 文章数据存在哪里

**没有数据库、没有后台 CMS**：所有文章就是仓库里的 Markdown 文件，跟代码一起用 git 版本管理。

| 内容 | 存放位置 |
|---|---|
| 文章正文 + 元数据 | `src/content/posts/**/*.md`（frontmatter 是元数据，正文是 Markdown） |
| 关于页正文 | `src/content/spec/about.md` |
| 字段校验规则 | `src/content/config.ts`（schema，字段写错构建会报错） |
| 分类 / 标签 | **不单独存储**，构建时从各篇文章的 frontmatter 现算（`src/utils/content-utils.ts`） |
| 搜索索引 | 不手写：构建时 pagefind 扫描 `dist/` 生成 `dist/pagefind/` |
| 封面图 | 文章同目录（如 `posts/guide/cover.jpeg`）或 `src/assets/` |

构建链路：Markdown →（Astro 校验 + 渲染）→ 静态 HTML 到 `dist/` → pagefind 生成搜索索引 → 部署。**改文章不需要动任何代码，重新构建即可生效。**

### 新增一篇文章

```bash
pnpm new-post -- my-first-post         # 生成 src/content/posts/my-first-post.md
pnpm new-post -- guide/getting-started # 也支持子目录（自动建目录）
```

也可以直接在 `src/content/posts/` 下手工建 `xxx.md` 或 `目录/index.md`（后者便于放同目录封面图）。脚本会写好 frontmatter 模板，标题默认取文件名，记得改。

- 列表排序：按 `published` 倒序（`content-utils.ts`），上一篇/下一篇由该顺序自动推导
- `draft: true`：**生产构建隐藏，但 `pnpm dev` 下仍可见**（方便预览）
- 新增文章后 `pnpm dev` 会自动刷新；但**搜索要重新 `pnpm build` 才会有新索引**
- 发布：`git add . && git commit && git push` → Vercel 自动重新构建

### frontmatter 字段（校验规则在 `src/content/config.ts`）

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 标题 |
| `published` | ✅ | 发布日期 |
| `updated` | | 更新日期 |
| `description` | | 摘要（首页卡片、OG 描述） |
| `image` | | 封面图，相对本文目录 |
| `tags` | | 标签数组 |
| `category` | | 分类 |
| `draft` | | `true` 则不出现在站点上 |
| `lang` | | 该文单独指定语言 |

- 正文可用扩展：提示框 `:::note` / `:::tip` / `:::important` / `:::caution` / `:::warning`、GitHub 仓库卡片 `::github{repo="owner/repo"}`、KaTeX 数学公式、代码块（行号 / 可折叠段落 / 语言徽章 / 复制按钮）、图片点击放大。

## 9. 头像与图片

**为什么头像是本地文件**：GitHub 头像地址（`avatars.githubusercontent.com`）在部分网络环境下加载失败，会出现"头像失效"。因此头像已下载到 `src/assets/images/github-avatar.png` 并交给 Astro 优化（输出 webp，带正确宽高），保证任何网络下都能显示。

**换头像后如何同步**：

```bash
pnpm sync-avatar                 # 默认同步 xiaochen56076 的头像
pnpm sync-avatar -- 其他用户名    # 同步指定账号
```

脚本会把 `https://github.com/<用户名>.png` 写入 `src/assets/images/github-avatar.png`，提交后站点即更新（GitHub 改头像后不会自动生效，需手动跑一次）。

**图片路径规则**（`ImageWrapper.astro`）：

| 写法 | 行为 |
|---|---|
| `/xxx.png` | 当作 `public/` 下的文件，原样输出 |
| `https://...` | 直接 `<img src>` 引用远端，**不经过优化，可能因网络失败** |
| `assets/images/xxx.png` | 相对 `src/`，经 Astro 优化（推荐） |

> `banner.src` 目前仍指向 GitHub 头像 URL。想更稳可以改成 `assets/images/github-avatar.png`。

## 11. 注意事项（踩过的坑）

1. **别让编辑器覆盖 `src/config.ts`**：如果 VS Code 里开着旧版本的 `config.ts` 缓冲区，保存时会把外部改动整段覆盖回去（本站已发生过一次：头像与导航栏链接被回退成模板默认值）。改完配置后请重新加载该文件。
2. **搜索界面与官方 demo 是一致的，别去"抄样式"**：已逐字节核对，`src/components/Search.svelte`、`Navbar.astro`、`styles/main.css`、`variables.styl`、`tailwind.config.cjs`、`ArchivePanel.svelte` 与官方 `main` 分支**仅差换行符**（本地 CRLF、官方 LF），图标用的是同一个 `material-symbols:search`。两者差别只在**数据**：`pnpm dev` 下没有 pagefind 索引，只显示两条中文模拟结果；`pnpm build && pnpm preview` 才是真实的索引结果（带关键词高亮、结果条数等于命中文章数）。
3. **关于页的 GitHub 卡片**由浏览器端请求 `api.github.com` 渲染，访客网络访问不了 GitHub 时只显示骨架。
4. **`site:` 已改成 `https://56076077.xyz/`**：文章底部的许可协议链接、RSS、sitemap、分享卡片现在都用这个域名。以后再换域名，改 `astro.config.mjs` 里那一行即可。
5. **中文标签/分类会生成百分号编码的 URL**（如 `/archive/?tag=示例` 之类），这是正常现象。
6. **文件编码约定**：UTF-8 无 BOM、CRLF。用脚本批量改文件时注意别写成带 BOM 的 UTF-8，否则可能引入整文件 diff。
7. 站内搜索的**索引在构建时生成**，新增文章后要重新 `pnpm build` 才能被搜到。
8. **不要在 `src/styles/*.css` 里用"跨文件 `@apply`"**：例如 `markdown.css` 里 `@apply link`，而 `.link` 定义在 `main.css`——这类写法能否解析取决于 CSS 分包结果，**Vite 缓存被 dev 服务器污染后会随机构建失败**（报 ```The `link` class does not exist```）。本站已把 `markdown.css` 中两处（`link`、`btn-regular-dark`）展开成具体工具类来解决。以后加样式时，跨文件的组件类请展开写，或把它定义在与使用处同一个文件里。
