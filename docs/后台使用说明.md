# 后台使用说明（Sveltia CMS）

> 后台页面：`src/pages/admin/index.astro`（对外就是 `/admin/`）
> 后台配置：`public/admin/config.yml`（对外就是 `/admin/config.yml`）
> 后台地址：`https://<你的域名>/admin/`（本地调试：`http://localhost:4321/admin/`）

---

## 1. 这个后台是什么

- 基于 [Sveltia CMS](https://sveltiacms.app/)，是一个**纯静态**的管理界面，跟着站点一起部署，**没有服务端代码、没有数据库、没有自建账号密码**
- 登录 = 用你的 GitHub 账号 + 一个只对本仓库有写权限的**访问令牌（PAT）**
- 保存文章 = 后台直接向 GitHub 仓库提交一次 commit → Vercel 自动重新构建 → 约 1 分钟后站点更新
- 因此它**不可能被"拖库"或爆破登录接口**：攻击者要进来，必须先拿到一个能写你仓库的 GitHub 令牌

**从哪里进**：站点导航栏**右上角的齿轮图标**（就在「主题色」调色板旁边），点开是与「主题色」同款的小面板，里面两条：「内容后台」和「GitHub 仓库」。手机/平板上齿轮会自动隐藏，入口改到右上角**汉堡菜单**里的「后台设置」。

## 2. 登录方式

后台支持两种登录（`public/admin/config.yml` 里的 `auth_methods: [oauth, token]`）：

| 方式 | 体验 | 前提 |
|---|---|---|
| **GitHub 授权登录（推荐）** | 打开 `/admin/` → 点「Sign in with GitHub」→ 授权 → 进入后台，**永远不用碰令牌** | 需一次性部署 OAuth 代理（已部署，见第 6 节） |
| 访问令牌（备用） | 手动创建并粘贴令牌，每台浏览器一次 | 不需要任何服务端 |

### 2.1 GitHub 授权登录（日常就用这个）

打开 <https://56076077.xyz/admin/> → 点 **Sign in with GitHub** → 在 GitHub 页面点 **Authorize** → 自动回到后台，已登录。换电脑、换浏览器都一样，点一下就行。

### 2.2 备用：访问令牌

万一 OAuth 出问题（或你临时想用令牌进），走这条：

1. 打开 <https://github.com/settings/personal-access-tokens/new>
2. **Token name**：`NK_Blog CMS`
3. **Expiration**：建议 90 天（到期后重新生成、重新登录一次即可）
4. **Repository access** → `Only select repositories` → 只选 **NK_Blog**
5. **Permissions** → `Repository permissions`：
   - `Contents` → **Read and write**（必须）
   - `Metadata` → Read-only（会自动勾上，无需改）
   - 其它权限一律不用给
6. 点 **Generate token**，复制形如 `github_pat_xxxxx` 的字符串（**只显示这一次**）

> **令牌能不能短一点？** 令牌长度是 GitHub 定的格式，没法自定义（细粒度是 `github_pat_` 开头、90 多字符；经典是 `ghp_` 开头、正好 40 字符）。想短就用**经典令牌**，见下面。另外：令牌**每台浏览器只需要粘一次**（存在 localStorage），不是每次登录都要粘。

### 想用更短的令牌：经典令牌 + 只勾 `public_repo`

因为 `NK_Blog` 是**公开仓库**，可以这样：

1. 打开 <https://github.com/settings/tokens/new>（经典令牌页面）
2. Note 填 `NK_Blog CMS`，Expiration 选 90 天
3. **只勾选 `public_repo`**（不要勾 `repo`、不要勾 `workflow` 等）
4. Generate → 复制 `ghp_` 开头、**40 字符**的令牌

- 长度只有细粒度令牌的一半左右，粘贴更快
- 权限范围其实更窄：只能动你的**公开仓库**（细粒度虽然只授权一个仓库，但经典令牌的 `repo` 范围是全部仓库，所以才要只勾 `public_repo`）
- 注意：以后若把博客仓库改成私有，这个令牌会失效，需要换成细粒度令牌

### 想彻底不用令牌：改成 GitHub 授权登录

见第 6 节（OAuth）。好处是点一下「Sign in with GitHub」即可，永远不用碰令牌；代价是需要部署一个 OAuth 中转服务（Cloudflare Worker，或在你已有的 Vercel 项目里加一个 serverless function），并注册一个 GitHub OAuth App。

## 3. 登录

1. 打开 `/admin/`
2. 点 **Sign In with Token / 使用令牌登录**
3. 粘贴令牌 → 进入后台

几个要点：

- 令牌保存在**该浏览器的 localStorage** 里，所以家里另一台电脑/另一个浏览器**首次都要粘一次**
- 清了浏览器数据、换了浏览器、令牌过期 → 都要重新粘一次
- 不建议在公共电脑上登录；用完记得登出并清除该站点数据

> 登录页还有一个「**使用本地仓库**」按钮：它让后台直接读写**你本机**的仓库文件夹（Chrome/Edge 支持），不碰 GitHub、也不需要令牌，适合本地预览排版。注意它改的是本地文件，不会自动提交，也不会同步到线上。

## 4. 日常写作流程

**文章 → New 文章**，然后按下面填：

| 字段 | 说明 |
|---|---|
| 标题 | 中文标题随便写 |
| **文件名（英文）** | **必填**，决定文章网址：填 `hello-astro` → 网址是 `/posts/hello-astro/`。只能用小写字母、数字、连字符（中文标题不会自动转成英文，所以这一步必须自己填） |
| 发布日期 | 默认今天，可改 |
| 更新日期 | 可选 |
| 摘要 | 可选，显示在首页卡片和分享卡片上 |
| 封面图 | 可选，**直接把图片拖进去**即可，会自动存到这篇文章自己的文件夹 |
| 标签 / 分类 | 可选，会自动汇总到侧栏的「标签」「分类」 |
| 草稿 | 勾上后**不会发布**（但本地 `pnpm dev` 能看到，方便预览） |
| 正文 | Markdown 编辑器，支持提示框 `:::note` 等、GitHub 卡片 `::github{repo="owner/repo"}`、数学公式、代码块 |

保存后：文件会写到 `src/content/posts/<文件名>/index.md`，封面图放在同一层，以一次 commit 推到 `master` 分支。

- 站点搜索索引在构建时生成，所以**新文章发布后会自动可搜**，不用额外操作
- 需要改回历史版本，可以去 GitHub 的提交历史里 revert 那一次 commit

## 5. 安全设计

| 措施 | 说明 |
|---|---|
| 无自建账号体系 | 没有密码库、没有会话服务，也就没有被撞库/爆破的入口 |
| GitHub 令牌最小权限 | 建议细粒度令牌，只授权 `NK_Blog` 一个仓库的 `Contents` 读写 |
| 建议开两步验证 | GitHub 账号开启 2FA，令牌被盗风险大幅下降 |
| 页面级加固 | `vercel.json` 给 `/admin/*` 下发 CSP（脚本只允许本站和固定版本的 unpkg CDN）、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: same-origin` |
| 不被收录 | 页面带 `noindex`，`robots.txt` 里也 `Disallow: /admin/`，并额外下发 `X-Robots-Tag: noindex` |
| 版本锁定 | `index.html` 里锁定 Sveltia 版本号，避免 CDN 上新版本被自动加载 |

**令牌泄露了怎么办**：GitHub → Settings → Developer settings → Personal access tokens → 删除该令牌 → 重新生成一个并在后台重新登录。令牌只能动这一个仓库，删除即失效。

## 6. GitHub 授权登录（OAuth）：实现与维护

**已经部署好了**：OAuth 代理就是本仓库里的一个 **Cloudflare Pages Function**，不需要另外开 Cloudflare Worker。

### 组成

| 部分 | 位置 / 值 |
|---|---|
| 代理代码 | `functions/api/[[path]].js`（对外路由 `/api/auth` 与 `/api/callback`） |
| GitHub OAuth App | GitHub → Settings → Developer settings → OAuth Apps → `NK_Blog CMS` |
| 回调地址 | Redirect URIs 里填 `https://56076077.xyz/api/callback` |
| 后台配置 | `base_url: https://56076077.xyz/api`、`auth_methods: [oauth, token]`、`auth_scope: public_repo` |
| 环境变量 | Cloudflare Dashboard → Workers & Pages → 该项目 → Settings → Variables and Secrets |

### 需要的环境变量（4 个）

| 变量 | 值 | 说明 |
|---|---|---|
| `GITHUB_CLIENT_ID` | OAuth App 的 Client ID | 公开信息，但仍建议走环境变量 |
| `GITHUB_CLIENT_SECRET` | OAuth App 的 Client Secret | **机密**，只存在 Cloudflare，**绝不进仓库** |
| `ALLOWED_GITHUB_LOGIN` | `xiaochen56076` | **白名单**：只有这些账号能登录（多个用逗号分隔） |
| `ALLOWED_DOMAINS` | `56076077.xyz` | 只允许自己的站点使用这个代理，防止别人白嫖 |

### 登录流程

```
点「Sign in with GitHub」→ 弹窗打开发 /api/auth → 302 跳到 GitHub 授权页
→ 点 Authorize → GitHub 回调 /api/callback?code=...
→ 服务端用 Client ID + Secret 换 access_token
→ 再查 GitHub /user，比对用户名白名单
→ 通过才把 token 交给后台窗口（postMessage 握手）→ Sveltia 存进浏览器
```

### 安全设计（本地 mock 测试 19 项断言全过）

- `Client Secret` **只在 Cloudflare 服务端**出现，从不进浏览器、不进 git 仓库
- 发起授权时种下 CSRF cookie，回调校验 `state`，不匹配立即中止
- 客户端只能申请**更窄**的 `auth_scope`；申请更宽的会被回落为默认值（防止有人用你的代理换到高权限 token）
- **非白名单账号连 token 都拿不到**——校验在回传之前，被拒时响应里不含任何 token
- `ALLOWED_DOMAINS` 限制只有你的站点能使用这个代理

### 维护

- **加共同作者**：`ALLOWED_GITHUB_LOGIN` 写成 `xiaochen56076,另一个用户名`（已支持逗号分隔），并把对方加为该仓库的 Collaborator
- **怀疑密钥泄露**：GitHub OAuth App 页面点 **Generate a new client secret** → 把新值更新到 Cloudflare 的 `GITHUB_CLIENT_SECRET` → 重新部署
- **撤销某人登录**：GitHub → Settings → Applications 取消授权，或改环境变量
- **想彻底不显示令牌入口**：把 `auth_methods` 改成 `[oauth]`

### ⚠️ 两个必须记住的坑（本站真实踩过，排查了很久）

**坑 1：`Client ID` / `Client Secret` 必须用「复制按钮」，绝不能手打**

本站部署时就因为手抄 `GITHUB_CLIENT_ID`：把第 5 位的**小写字母 `l` 写成了数字 `1`**、第 13 位**漏了一个 `b`**（19 位，正确的是 20 位）。

这个错的表现极具迷惑性：

- **未登录时**打开授权地址，GitHub 会正常把你重定向到**登录页** → 看起来一切正常
- **登录之后**它才真正处理授权请求，发现找不到这个应用 → 直接返回 **GitHub 的 404 页面**（`This is not the web page you are looking for.`）

很容易误判成"网络被墙 / 浏览器缓存 / 扩展拦截"（这几条我都验证过，全都不是）。

正确做法：

1. GitHub OAuth App 页面点 **Client ID 右侧的复制按钮**（不要手打），直接粘贴到 Cloudflare
2. Client secret 同理：点 **Generate a new client secret** 后**复制**再粘贴（明文只显示一次）
3. 粘贴后核对一遍，特别注意 **`l / 1 / I`**、`O / 0`、`b / 6` 这类形似字符
4. 自检：`GITHUB_CLIENT_ID` 正常是 **20 位**，长度不对基本就是抄错了

**坑 2：改完 Cloudflare 环境变量，必须「重新部署」才会生效**

Cloudflare 不会把新变量自动应用到已运行的 Functions 上。改完变量后：

**Deployments（部署）→ 最新一次部署 → `⋯` → Retry deployment（重试部署）**，等 1~2 分钟。

不重新部署的现象：`/api/auth` 依旧返回「服务端未配置 GITHUB_CLIENT_ID / GITHUB_CLIENT_SECRET」。

> 顺带：**推送代码也会触发一次部署**，所以"改变量"和"改代码"往往可以合并成同一个动作。

**排查这类问题的正确姿势**（照这个顺序，两步就能定位）：

1. 浏览器直接打开：`https://56076077.xyz/api/auth?provider=github&site_id=56076077.xyz&scope=public_repo`
   - **302** 且 `Location` 指向 `github.com/login/oauth/authorize?client_id=…` → 代理正常 ✅
   - 返回「未配置」→ 环境变量没生效（回到坑 2）
   - 返回博客首页 HTML → Functions 没被识别（看构建日志里有没有 `Found Functions directory`）
2. 再直接打开上一步 `Location` 里的那个 GitHub 地址
   - 看到登录页/授权页 → `client_id` 正确 ✅
   - **登录后**变成 404 → `client_id` 错了（回到坑 1）

## 8. 已知限制与常见问题

1. **现有的 `guide` 文章在后台看不到**：它存放在子目录（`src/content/posts/guide/index.md`），当前集合只列出文章根目录下的文件。后台新建的文章都会存成 `文章名/index.md`（和 guide 一样的结构），管理起来没有问题。如果要把 guide 也纳入后台，需要开启嵌套集合（nested collection），说一声即可加。
2. **中文标题不会自动生成英文网址**：所以「文件名」字段是必填项。
3. **`pnpm dev` 本地也能打开 `/admin/`（已实测 200）**，而且登录后的操作是**真的**在改 GitHub 仓库，不是在改本地文件。想改本地文件，用登录页的「使用本地仓库」，或直接编辑 Markdown。
4. **后台直接提交到 `master`**，没有审批流（Editorial Workflow）。个人博客够用；如果以后想先提 PR 再合，可以改成 editorial 工作流。
5. **后台界面语言**跟随 Sveltia 自身的语言包（浏览器语言有对应语言包时会自动切换；没有就是英文界面）。功能不受影响。
6. 上传图片走仓库存储，**GitHub 不支持 Git LFS**，所以不要往仓库里塞大量/超大图片（会拖慢 git 操作）。
7. **`@apply` 跨文件依赖的坑（已根治）**：`src/styles/markdown.css` 里原本写着 `@apply ... link ...` 和 `@apply btn-regular-dark ...`，而这两个类定义在 `main.css`。这种"跨文件 @apply"能否解析**取决于 CSS 分包结果**——实测在 Vite 缓存被 dev 服务器污染后，`pnpm build` 会随机报 ``The `link` class does not exist`` 而失败。现已把两处都展开成具体工具类（视觉等价：已对比产物 CSS 与截图）。构建恢复确定性：实测"先跑 `pnpm dev` 污染缓存、再 `pnpm build`"也能通过。因此后台页面那段 `<style>` 不再是必需的（留着无害，注释里仍写着原因）。
8. **后台入口对所有访客可见**：齿轮按钮谁都能看到，点开也只是登录页，没有令牌什么都做不了（安全模型不依赖"藏起来"）。若你希望它只对自己可见，可以改成条件显示（例如浏览器 localStorage 里有某个标记、或按了特定快捷键时才出现）——说一声即可加。
9. **入口面板的文案写死在组件里**（`AdminMenu.svelte` 中的「后台设置」「内容后台」「GitHub 仓库」），没有走 i18n。本站只用 `zh_CN`，所以没有影响；以后若要支持多语言，需要往 `src/i18n/i18nKey.ts` 与 `languages/*.ts` 补对应键。
