# 侧栏音乐播放器说明

> **音频该放哪、怎么长期扩展**（仓库 vs Cloudflare R2、音频规范、待实施脚本）见另一篇：
> **`docs/音乐与音频存放方案.md`**

## 1. 现在是什么样

| 项 | 说明 |
|---|---|
| 位置 | 侧栏「标签」卡下方（`SideBar.astro` 里的 `<Music>`） |
| 侧栏小卡 | 封面 + 曲名 + 歌手 + 上一首/播放/下一首 + 「列表」按钮 |
| 展开 | **点击封面** → 封面用 FLIP 动画「飞」到左下角迷你窗，迷你窗淡入 |
| 迷你窗 | 封面、曲名/歌手、播放控制、进度条（可拖动）、**播放列表**；`Esc` 或右上角 `×` 收起 |
| 切歌 | 点列表任意一首即可播放；播完自动下一首 |
| 跨页不中断 | 播放器在 Swup 容器之外，站内切页时音乐继续播（整页刷新会回到第一首） |
| 定位 | 迷你窗 `fixed` 左下角，手机端距边 1.5rem、桌面 2rem（不贴边），层级低于导航栏、高于回到顶部按钮 |

## 2. 换成你自己的音乐

编辑 `src/config.ts` 的 `musicConfig`：

```ts
export const musicConfig: MusicConfig = {
	enable: true,          // 关掉就整块隐藏
	title: "音乐",
	autoplay: false,       // 多数浏览器会拦截自动播放，建议保持 false
	playlistUrl: "",       // 见第 4 节（预留的接口）
	tracks: [
		{ title: "曲名", artist: "歌手", url: "https://你的服务器/music/a.mp3", cover: "https://你的服务器/music/a.jpg" },
	],
};
```

- `url` 是**音频直链**（mp3 / m4a / ogg 等），`cover` 可省略（省略时显示音符占位图标）
- 现在配置里的 3 首是**示例曲目**（SoundHelix 的公开测试音频），只为让你先看到效果，正式发布请替换

## 3. 音乐文件放哪里（重点）

**不要把音频放进这个仓库、也不要指望 Vercel 托管音频**：

- GitHub 仓库有体积限制，音频会让 clone / pull 变得很慢
- Vercel 的流量配额会被音频迅速吃光（音频是持续请求，不像图片只请求一次）
- 版权问题：公开托管他人作品的风险由你自己承担

推荐放法：

| 方案 | 说明 |
|---|---|
| **对象存储**（阿里云 OSS / 腾讯云 COS / 七牛 / Cloudflare R2） | 最省事：上传后设成公共读，把直链填进 `url` 即可 |
| **自己的服务器 + nginx** | 把音频放静态目录，例如 `https://你的域名/music/a.mp3` |
| 免费音频床 / 图床 | 不推荐，随时可能失效或限速 |

几个实践建议：

- `<audio>` 播放**不需要 CORS 头**（跨域也能播），所以对象存储默认设置通常就能用
- 码率 128–192kbps 的 mp3 足够；首页不会加载音频，**只有点了播放才发起请求**，不影响首屏速度
- 封面图建议压到 200KB 以内（它会随卡片一起加载）

## 4. 关于「接入 QQ 音乐登录、查看喜欢和创建的歌单」

**结论：纯静态站点做不到，必须你自己有一台服务器。** 原因如下（这是事实层面的限制，不是偷懒）：

1. **QQ 音乐没有面向第三方 Web 应用的官方授权接口**——不像 GitHub 有 OAuth，可以「点一下授权，然后读你的仓库」。QQ 音乐没有这种开放能力。
2. 社区里的各种「QQ 音乐 API」项目，都是**逆向它的私有接口**：用 QQ 扫码登录拿到 cookie（`uin` + `qqmusic_key`），再去请求 `y.qq.com` 的数据。浏览器直接请求会被 **CORS 拦死**，所以中间必须有一个服务端代理。
3. 那个 cookie **等同于你 QQ 的登录凭证**：只能存在你自己的服务器上，**绝对不能放进这个静态站点**（放进去等于对全网公开）。
4. 即使接上了：VIP / 数字专辑 / 有 DRM 的曲目**拿不到可播放地址**（或只有试听片段），能正常播的主要是免费曲目。
5. 这类逆向接口**随时可能被腾讯改动而失效**，且使用它可能违反 QQ 音乐的用户协议——风险需要你自己判断，我不建议把它当成长期方案。

**播放器已经为将来预留了接口**：等你有了服务器（自建 API、或自建代理），只要把地址填进配置：

```ts
playlistUrl: "https://你的服务器/api/playlist",
```

接口返回 `MusicTrack[]` 的 JSON 即可，播放器会优先使用接口数据、失败自动回退到 `tracks`：

```json
[
  { "title": "曲名", "artist": "歌手", "url": "https://.../a.mp3", "cover": "https://.../a.jpg" }
]
```

到时候把接口字段发我，我帮你适配（字段名不同也没关系，中间加一层映射即可）。

## 5. 已知限制 / 以后可以加

- 目前**没有**：音量控制、歌词、随机/循环、播放记忆（刷新回到第一首）、系统媒体控制（Media Session，锁屏/耳机按键）
- `autoplay: true` 在多数浏览器会被拦截，需要用户先点一次播放（这是浏览器策略，不是 bug）
- 音频加载失败时，卡片下方会显示一行提示（例如 url 写错或文件不可访问）
- 想加什么告诉我：音量条、歌词、记住上次播放、随机循环都很容易补

## 6. 相关文件

| 文件 | 作用 |
|---|---|
| `src/config.ts` | `musicConfig`：开关、标题、曲目列表、接口地址 |
| `src/types/config.ts` | `MusicConfig` / `MusicTrack` 类型定义 |
| `src/components/widget/MusicPlayer.svelte` | 播放器本体：音频逻辑、侧栏小卡、迷你窗、FLIP 动画、播放列表 |
| `src/components/widget/Music.astro` | 侧栏小卡外壳（套用主题的 `WidgetLayout`，与「分类」「标签」同款） |
| `src/components/widget/SideBar.astro` | 决定它排在「标签」下方 |

> 实现细节备忘：迷你窗在 `onMount` 时被移动到 `document.body` 下——因为侧栏祖先元素带有入场动画/变换，`position: fixed` 会被这些祖先"劫持"定位。另外 Stylus 里不能写 CSS 的 `min()`/`max()`（会被当成 Stylus 数学函数报错），所以宽度用的是 `width` + `max-width`。
